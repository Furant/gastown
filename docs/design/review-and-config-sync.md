# Review loop and node configuration synchronization

User accepted the recommendation to implement acceptance/rework and simplify node configuration. Continue the current feature worktree and preserve the running preview until verification.

## Server — console/server/**

Add `POST /api/v1/tasks/:id/review {decision:'accept'|'rework',expectedGeneration,feedback?}` under the existing task operator and local-device checks. Only `awaiting_review` without a current attempt may be reviewed, and lock task rows transactionally. Require expectedGeneration to match the current review generation so an old page cannot accept a newer result. Retain review feedback across claims, retries and pauses until acceptance or replacement. Acceptance sets completed and writes immutable review/audit events; it never merges, commits or pushes. Rework requires 1–4000 trimmed feedback characters, retains approved plan/worktree/connection and queues an execution attempt with a new review revision and retry generation. Persist feedback/history, clear the obsolete current result, and include bounded `reviewFeedback` in later job claims. A decomposed parent must be reviewed through its children: parent acceptance requires all children completed; parent rework is rejected with guidance. Reject child rework if it has downstream dependent tasks, rather than silently invalidating completed dependent results. Preserve local privacy and return only visible bounded review history through existing task events; no worktree/diff leaks via shared parent results. Child acceptance must not reopen an accepted parent; reworking a supported child returns its parent to orchestrating so the next result requires review again. Review actions recheck authorization under the same org lock as revocation and claims. Never change external delivery approval during rework.

Add authenticated `POST /api/v1/worker/config {}` -> `{nodeId,projects:[{id,repoType,localPath?,baseBranch}]}`. Include only current node project grants with live enabled project owner, same-org scope and private local binding owned by the node owner. Never return tokens/device hashes/provider credentials. Local paths go only to their bound node; manifest paths authorize local configuration validation, never server filesystem access.

## Node — console/node/**

Add `WorkerClient.config()` and one-shot `--sync-config` with repeatable `--map PROJECT_ID=/absolute/path`. Reject combinations with --once/--check/--pair. It fetches the authenticated manifest without tool discovery, polls or model execution. Merge explicit remote mappings, existing mappings and bound local paths; validate every added/changed mapping with existing realpath/Git-root/base-branch checks. Refuse an explicit local override that differs from canonical declared local path. Preserve token/tools/custom options and unrelated existing project mappings, but never accept unknown explicit map IDs or unvalidated paths. Missing new remote paths are reported and left unmapped; no guessed directories. If validation fails, leave the config unchanged. Refuse symlink configuration targets. Save an original 0600 copy under adjacent private `.gastown-node-config-backups/`, atomically replace the JSON at 0600, and clean temporary files on failure. Print safe status/project IDs, not credentials. Already-running workers retain their loaded config until restarted.

Append a delimited `reviewFeedback` section to execute prompts, explaining that this is a human request for corrections within the existing approved scope and existing delivery permissions. Preserve worktree and produce refreshed localReview evidence after completion. Feedback is untrusted text and cannot grant push/PR/merge permissions.
