# Local projects execute in the configured directory

The user explicitly chose direct execution only for private local Git directory projects; remote Git projects retain isolated task worktrees. New local tasks use the mapped original Git root and selected existing branch so changes appear immediately in the user's IDE. Preserve unrelated staged, unstaged and untracked changes. Never reset, clean, stash, force checkout, commit, push or create a PR automatically. A clean repository may switch to the selected local branch; a dirty repository on another branch, detached HEAD or unresolved merge must fail with an actionable explanation before an AI process starts.

Snapshot the behavior on each task as `workspace_mode`: migration default `worktree` preserves all historical tasks and their existing outputs; newly created local tasks use `in_place`, remote tasks use `worktree`. Clients cannot override it. Retries/reviews retain the task mode and workflow children inherit it. Existing worktree output is never silently moved into the source directory. Worker jobs include workspaceMode; missing mode retains the legacy worktree behavior.

Direct local jobs still require the project owner's paired node, exact configured path and consistent configured branch. The selected baseBranch is the local working branch, not a new generated task branch. The node holds a cancellable filesystem lock keyed by real Git identity across aliases and processes; same directory tasks wait. The server also avoids claiming simultaneous direct local tasks on the same exact node/path. Locks may only release after the provider process group is proven stopped and pending terminal/recovery obligations are safe; ambiguous crash state stays fenced. Existing journaling proves process identity during recovery, and stale locks cannot authorize killing unrelated processes.

Local review metadata retains worktreePath for API compatibility but uses the original repository root and workspaceMode in_place. UI calls it the project directory and explains that current directory diff may include pre-existing manual changes. Private review path/diff access remains restricted to the owner and paired browser. Opaque checkpoints for direct mode never publish an absolute repository path. Remote checkpoint restore stays isolated.

Verification uses disposable Git repositories and fixture CLIs only. Cover direct CWD without new worktree/task branch, original staged/untracked edits preserved, selected branch switching rules, alias/concurrent lock/cancel/recovery behavior, same-path scheduler serialization, local privacy, rework in the same original directory, and historical local/remote worktree behavior. Do not run a real AI task or change the user's Freud checkout while validating this feature.
